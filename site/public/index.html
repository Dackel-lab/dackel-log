Recursos

Observabilidade sem abrir a porta para vazamentos

O necessário para diagnosticar produção, sem devolver detalhes internos ao cliente.

Correlação ponta a ponta

X-Trace-Id em toda resposta, inclusive 2xx. Nos erros, o mesmo valor aparece no ProblemDetails e nos logs.

Cadeia recursiva

InnerException e AggregateException serializados como objetos, com MaxDepth configurável e proteção contra ciclos.

Sanitização em duas camadas

CPF, CNPJ, e-mail, bearer token e pares password=... são mascarados antes de chegar ao log ou à cadeia.

JSON compacto no stdout

Console com CompactJsonFormatter, pronto para coleta automática por Grafana, Datadog ou outro agregador.

Sem @x cru

A exceção não é anexada como texto bruto. Tipo, mensagem sanitizada e stack trace ficam na cadeia estruturada.

Middlewares prontos

TraceIdMiddleware, logging de exceções e log de requisição com status, duração e enriquecimentos declarativos ou programáticos (ex.: tenant).

Sem Dackel.Log

Mensagem crua na resposta e no log

System.InvalidOperationException:
  Falha com CPF 123.456.789-09
  e password=Segredo123
  ---> inner com CNPJ 12.345.678/0001-90

PII, segredo e detalhes internos expostos.

Com Dackel.Log

Cadeia sanitizada e consultável

"ExceptionChain": [
  { "Depth": 0, "Message": "Falha com CPF ***" },
  { "Depth": 1, "Message": "inner com CNPJ ***" }
]

Cliente recebe um erro seguro; suporte localiza pelo traceId.

Início rápido

Quatro linhas no pipeline

Registre o componente e adicione os middlewares na ordem correta.

using Dackel.Log;

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddProblemDetails();
builder.AddStructuredLogging("Minha.Api")
    .EnrichStructuredLogging("Tenant", (context, services) =>
        services.GetRequiredService<ITenantProvider>().GetTenant(context));

var app = builder.Build();

app.UseTraceId();
app.UseRequestEnrichment();
app.UseStructuredRequestLogging();
app.UseExceptionHandler();
app.UseExceptionLogging();

app.MapControllers();
app.Run();

A ordem importa: o trace id é o mais externo; o log de exceção fica dentro do handler.

exceptionLogger.LogError(
    exception,
    "Falha não tratada ao processar {HttpMethod} {RequestPath}",
    [httpContext.Request.Method, httpContext.Request.Path.Value],
    traceId: TraceIdMiddleware.GetTraceId(httpContext));

Se o handler também logar, use ExceptionLoggingMiddleware.WasLogged(httpContext) para evitar duplicidade.

Configuração

Padrões seguros, ajustáveis quando necessário

O comportamento padrão já cobre a maioria dos cenários de produção.

ExceptionLogging:MaxDepth 10 níveis

Profundidade da cadeia de exceções. Ao exceder, o evento marca ExceptionTruncated: true. Faixa válida: 1–50.

Sink Console JSON

CompactJsonFormatter no stdout. Não adicione WriteTo no appsettings para evitar eventos duplicados.

StructuredLogging:Enrichments Declarativo ou por código

Matrícula e unidade via Claim, Header, Item ou User:Name. Tenant e demais valores de serviço usam EnrichStructuredLogging(). Nomes e headers sensíveis são rejeitados no startup.
